# 演出結構（只談結構，不談視覺）

什麼時候讀：流程第 8 步（交給演出層）；或規則設計時想知道「這條規則演得出來嗎」。

畫面風格、顏色、UI、引擎（three.js 或別的）都由新專案自己決定。這裡只留原作（作者先前做的一款 GROW 式遊戲）演出層的**結構**：回合怎麼播、什麼能有字、節奏上限的起點。數字都是起點，不是規定。

---

## 0. 規則層交給演出層的東西（交接清單）

流程第 8 步要把這份清單（填上這款遊戲的實際內容）寫成一份文件，交給演出層的設計：

- **事件種類與欄位**：`placed`（`item`、`to`、`story`）、`grow`（`item`、`from`、`to`、`via`、`jump?`）、`fx`（`item`、`cause`、`delta?`、`lock?`、`flag?`、`story?`）、`stall`、`wait`（`waits[{ item, for }]`）、`after`。`via` 是真的讓條件成立的幫手，跳級先列第一級的幫手——演出層靠它決定「誰走去誰那裡」。
- **哪些旗標是鎖**：`lockFlags(spec)` 回 `{ 被鎖的物品: 旗標名 }`。演出層只看 `{ lv, flags }`，旗標立了就當那個物品鎖住了。
- **搗蛋**：`grippedBy(state, id, spec)` 回抓住 id 的物品；旗標 `gripped_<id>` 的值就是它。
- **純函數原則**：所有外觀都是 `{ lv, flags }` 的純函數。`foldEvent(view, event)` 把一個事件疊上去。所以「跳過」= 直接套最終狀態；RESET = 重建。
- **收尾考驗與結局**：`resolve(state, spec)` 回 `{ id, title, kind, finale, extras }`。**收尾畫面照 `finale` 挑，結局標題照 `id`**——同一個結局可能對應不同的考驗結果（dragon-valley 的「結界未成」包含命中與被龍趕走兩種，`line` 只寫兩種都成立的事）。
  - **沒有 `FINALE` 的遊戲**（考驗本身是順序裡的物品，例如玩家放下的流星雨）：`finale` 永遠是 `null`，收尾畫面照 `id` 挑；交接文件寫明「沒有收尾考驗，考驗是哪個物品、在哪一回合發生」，演出層才不會去找一段不存在的考驗動畫。
- **每個結局的代表順序**（`expected.js` 的 `REPRESENTATIVE`）：演出層的節奏工具、截圖都用同一組順序。
- **劇透表**（`npm run solutions`）：正解逐回合表就是演出的分鏡起點。
- **`STORIES`**：每個物品放下與每一級的一句話——給演出設計參考，不上畫面。

## 1. 一回合怎麼播

**D1. 引擎事件 → 每個事件一段劇本 → 一串「拍」→ 接成時間軸依序播。**
- 拍的種類：走、泡泡、小動作、套用、LEVEL UP、鏡頭、等、同時。
- 事件之間不重疊；同一時間只有一個主角在演，其他角色做日常動作。沒寫劇本的事件用預設劇本：套用 → LEVEL UP。

**D2. 一回合裡的順序。**
1. 放置。
2. 放下物品的 Lv2，緊接著放置演（前提是條件在回合開始就成立）。
3. 其他物品的升級，照引擎順序。
4. 災害鎖住的反應拍。
5. 等待的物品：只演畫面層的虛構成長，或什麼都不演。
6. 回合結算：中央地標（如果有）跳階。
- 為什麼要第 2 點：看錄影時以為某棟建築「升級兩次」，其實是剛放下的物品的 Lv2 被排到四個物品之後才演，跟放置脫節了。

**D3. 鏡頭跟著事件走。** 每個事件前平移拉近到那一格；同一格的連續事件不重複平移；物品之間空 0.4 s；回合最後回全景。鏡頭不帶路，觀眾就不知道要看哪裡（這偏離了 GROW 的「鏡頭不動」）。

**D4. LEVEL UP 的規矩。** 只冒在這個事件改變的零件上方，停約 1 s；放置不標；掉級是灰色的 LEVEL DOWN；跳級只冒一個大一號的 LEVEL UP，不冒「×2」。

**D5. 升級只發生在「玩家選擇造成的回合」。** 放置回合，加上照一般回合演的收尾回合；沒有自動倒數、沒有趕工蒙太奇、沒有倍速。終局不是引擎回合：遊戲層算好結局，再合成事件交給演出層。

**D6. ◆ 關鍵級：故事上的大節點，可以演完整劇本、回全景。** 每回合的秒數上限隨 ◆ 個數加。跳級不等於 ◆。

## 2. 節奏上限（原作的數字，當起點）

**D7.**
- 放置回合 4 s ≤ t ≤ 60 + 8 × (◆ − 1)；收尾回合同上限。
- 一般劇本 ≤ 3.5 s、◆ ≤ 6 s。鎖住反應 ≤ 1.5 s。
- 終局：真結局 ≤ 22 s、壞結局 ≤ 16 s；各結局收尾 ≤ 5.5–7 s。正解整局約 249 s。
- GROW 參考：GROW Island 一回合 10–58 s，越後面越長，平均約 30 s。
- 修剪原則：留主意（走到、按下、出現、LEVEL UP），砍停頓與重複鏡頭，不加速。

## 3. 終局

**D8. 終局的結構。**
1. 警告：全場抬頭、「！」，約 3.3 s。
2. 收尾考驗，結果之一（`finale`）。
3. 收尾：真結局一段，每個壞結局各一段。
4. 停約 2 s，不能跳過。
5. 沒有結局卡：畫面本身就是結局。RESET 鍵開始發亮，結局記進圖鑑。

## 4. 失敗怎麼讀

**D9. 失敗靠五個無字的管道讀出來。**
1. 災害鎖住的反應拍。
2. 連鎖：依賴的東西跟著停，結算一排低等級。
3. 搗蛋角色守在出問題的那棟門口（規則層的 `wait` 事件告訴它去哪）。
4. 卡住的東西畫面上虛構成長，或改成壞掉的樣子（只在演出層，不動求解器）。
5. 每個結局自己的收尾。
- 撲空、拜訪、起因提示、提示泡泡原作都試過又拿掉（見 [choices.md](choices.md) 的「可讀性」）。

## 5. 東西怎麼出現、角色、文字

**D10. 東西怎麼出現和消失。** 建築只在外形真的改變時才從底部長出來（停一下、長高、略過頭再回來，約 0.8 s）；只換顏色的原地換；拿掉的零件縮下去；人一律走進場，不瞬移；建築上沒有閃白、發光、點頭這類強調（原作全部試過又拿掉；要加先問）。

**D11. 泡泡只給角色表達情緒，不當提示用。** 「！」注意到、「……」思考或等待、「♥」成功、「♪」開心、「？」困惑。GROW 會用圖框泡泡表示「他想要什麼」；原作試過的「等待圖框」最後拿掉了，因為它等於提示。

**D12. 角色的延續性。** 角色跨回合存在；蓋房子的人直接變成住在裡面的角色，人數少；每次升級留下一個會動的東西。

**D13. 允許出現的文字。** 場景上只有 LEVEL UP（有降級才有 LEVEL DOWN）；UI 上只有物品列的 Lv.n、放置順序、圖鑑裡已看過結局的名稱與計數。`STORIES` 只用在除錯、劇透表和求解器輸出。

**D14. 跳過與減少動態。** 跳過鍵只在演出中啟用；結局前的停頓不能跳；跳過 = 立刻套用最終狀態；`prefers-reduced-motion` 等於每回合直接跳過。前提是外觀都是 `{ lv, flags }` 的純函數。

**D15. 音樂跟著場景長。** 已放幾個物品就有幾層聲部；壞結局收尾後每小節掉一層；災害期間 BGM 變悶。音效只在玩家動作、LEVEL UP／DOWN 和終局。全部即時合成、有靜音鍵。

**D16. 物品列的結構。** N 格，每回合結束寫上 Lv.n，MAX 變色，有放置順序徽章，最後一格是跳過鍵。「怎麼玩」只有三句：一次放一個、順序會改變結果、全部 MAX 看真結局。
