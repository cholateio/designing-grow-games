# 原作的大轉彎（新專案可以預先避開的路）

什麼時候讀：開工前花兩分鐘看一遍，知道哪些路原作走過又退回來；或使用者提出某個做法時，查它是不是已經被推翻過。

「原作」是作者先前做的一款 GROW 式遊戲（8 個物品、唯一正解、多個壞結局）。它在大約兩週半的開發裡，規則與演出大改了十幾次。下表每一列是一次轉向，照先後排列：改了什麼、被什麼觸發。觸發多半是作者看實際錄影後的感想。

| 順序 | 轉向 | 觸發 |
|---|---|---|
| 1 | 初版：兩條正解兩個真結局、每回合每物品最多 +1、放下當回合不長、全部放完後倒數 3 回合 | — |
| 2 | 演出改成旅程式：一個主角、泡泡、結果出現在停下的地方 | 建築原地縮放看起來很怪 |
| 3 | 級數分層、每物品一個跳級、加長故事鏈 | 故事說不完、建築變化不明顯 |
| 4 | 最終章：宣告、趕工三回合、收尾考驗、尾聲 | 結局卡直接跳出來、場景都好好的，沒有高潮 |
| 5 | 放下當回合就長、每級預設可跳、只留一輪最後成長 | 全部放完後的大升級很怪 |
| 6 | 每一級都要觸發者、拜訪與撲空演出 | 後期看不出因果 |
| 7 | 回到 GROW：預設自己長、少數阻擋、少數有故事的跳級、拿掉拜訪 | 拜訪演出像角色瞬移過來點個頭就升級，讀不出因果 |
| 8 | 連鎖：靠樞紐的七格加上樞紐條件 | 樞紐壞了，全場照樣長滿 |
| 9 | 唯一正解、條件從正解回推、災害改成放下時一次檢查（後縮成 3 級）、撲空刪除、降級當回合不升 | GROW 只有一條正解 |
| 10 | 起因提示整個刪除 | 連「彈一下」都嫌多 |
| 11 | 災害與搗蛋持續有效，正解因此換順序；災害不降級；結局卡拿掉；收尾考驗換了造型 | 試玩者問「為什麼我後放的沒受影響」；避免影射真實衝突 |
| 12 | 畫面上的字只剩 LEVEL UP／DOWN | 小字越少越好 |
| 13 | 每個壞結局有自己的收尾；永遠當不了標題的結局刪除 | 大多數的局結尾同一張圖 |
| 14 | 畫面層的虛構級數、抓住一直持續到離開窗口、劇本長度上限 | 畫面停著不動、後期偏長 |
| 15 | 能力只在有效那一級才畫出來、一個結局畫面改三版、單一順序的結局刪除、結局圖鑑 | 能力看起來有了卻沒發揮、不合理；結局畫面讓人不舒服 |
| 16 | 音樂跟著場景長 | — |

## 從這張表讀出來的五件事

1. **唯一正解是最晚才定、卻最根本的決定。** 前面大半時間在兩條正解、預設跳級、每級觸發者之間來回；一旦定成唯一正解，條件從正解回推，很多問題（錯在哪看不出來、錯的順序也七個 MAX）一起消失。新專案第一天就定唯一正解。
2. **「自動長」的段落每次都被拒絕。** 倒數三回合、趕工蒙太奇、每級預設跳級，都因為「不是選擇造成的升級」被拿掉。升級只發生在玩家選擇造成的回合。
3. **提示的形式一個一個被拒絕。** 拜訪、撲空、起因光、彈一下、等待圖框、說明字、結局卡。最後留下的失敗管道全部是「場景本身的狀態」（見 [presentation.md](presentation.md) 的 D9）。
4. **災害要「持續有效」，玩家才覺得合理。** 試玩者第一個問題就是：災害還在時才放下的東西，為什麼沒事。這條改了正解。
5. **結局要分得開。** 大多數的局結尾同一張圖時，玩家覺得結局只有一個。每個壞結局都要自己的畫面，而且要看得懂。
